# 과거 시점 차트 검증 · price-sequence-v4

## 원인 진단

코드에서 확인한 오류: 과거 후보 구간의 판독 제한을 현재 판단의 부족 항목 배열에 먼저 넣고, 현재 요약에서 그 첫 항목을 사용했다. 따라서 과거 ‘6월 고점권’ 오류가 현재 오른쪽 끝의 판단 이유처럼 표시될 수 있었다. 현재 오류와 과거 구간 오류를 분리했다.

제공된 결과는 화면 캡처이며 실제 모델 원본 JSON은 없다. 모델이 종목명과 오른쪽 끝 자체를 잘못 읽었는지, 봉을 얼마나 반환했는지는 확정할 수 없다. 앱의 기존 전송 경로는 원본 Data URL을 전달하며 서버의 이미지 축소는 없었다. 제공업체 내부 이미지 처리는 확인하지 못했다. 오늘 날짜와 오래된 차트 날짜를 비교해 거절하는 로직도 없었다. 형식 오류는 502로 구별하며 패턴 없음으로 바꾸지 않는다.

## 첨부 사례의 시각적 확인

이는 사람이 첨부 이미지를 읽은 관찰이며 실제 API 재분석 결과가 아니다.

| 항목 | 관찰 및 한계 |
| --- | --- |
| 종목 | 왼쪽 위 우리기술 · 일. 일부는 추세선 도구 표시에 가려짐 |
| 기준 위치 | 오른쪽 끝, 2026년 초 급등 이후 봉. 2025년 6월 구간을 현재로 삼으면 안 됨 |
| 9,500 | 마지막 봉 높이에 연결된 오른쪽 가격표로 보임. 해당 봉 마감 완료 여부는 이미지로 확정하지 않음 |
| 8,120 | 별도 파란 수평선의 가격표. 마지막 봉 종가로 대체하지 않음 |
| 고저점 등락률 | 화면 밖 현재가가 반영됐을 수 있으므로 당시 판단에서 제외 |

종목·날짜·가격은 운영 코드에 정답으로 고정하지 않았다.

## 구현

- `reference-policy.mjs`: 입력 이미지 오른쪽 끝 기준, 관찰 스키마, 가격표 역할, 날짜 출처, 실제 사용·제외 봉, 업로드 시각 분리. 날짜 미확인은 구조 판독 불가와 별개다.
- `server.mjs`: 관찰 후 봉 구조를 반환하는 엄격한 응답 스키마, 전체 이미지와 최근 구간 확대 이미지 전송, 기준일보다 뒤의 날짜가 관찰되면 범위 오류. 이미지 내용·API 키를 로그에 남기지 않는다. 진단에는 바이트 수·해시·확대 여부만 포함한다.
- `chart-assessment.mjs`, `analysis-policy.mjs`, `sequence-policy.mjs`: 현재·과거 부족 항목 분리, 오른쪽 끝과 추출 봉 위치 불일치 감지, 과거 행동 제목, 신호 확인 날짜 보존.
- `public/scope.js`: 실제 픽셀 자르기와 사각 영역 가리기. 확대 이미지는 잘라낸 결과에서만 생성한다. 미래 봉이 확대 이미지에 재등장하지 않는다.
- `public/review.mjs`: 최초 판단·정책·모델·조건을 복제해 고정, 해시 검증, JSON 내보내기/가져오기, 별도 사후 평가. 이미지와 키는 고정 파일에 포함하지 않는다. 해시는 서버 서명이 아니며 악의적 재작성 방지 수단은 아니다.
- `public/index.html`, `app.js`, `style.css`: 목적·선택 기준일·봉 상태·범위 편집, 당시 행동 중심 결과, 실제 사용/제외 봉, 관찰 정보와 사후 평가 UI. 크림/오렌지 디자인 유지.

## 사용 절차 및 한계

1. 과거 시점 검증을 선택하고 선택 기준일, 마지막 봉 상태, 보유 여부·기간을 설정한다. 과거 모드만으로 봉을 마감 완료 처리하지 않는다.
2. 기준일이 이미지 중간이면 범위 편집으로 오른쪽 미래 봉을 실제로 잘라낸다. 미래 가격을 드러내는 표시·매물대도 드래그로 가린다. 날짜→픽셀 자동 매핑은 하지 않으므로 사용자가 끝 위치를 확인해야 한다. 정확히 매핑할 수 없으면 그 날짜에서 끝나는 별도 이미지를 사용한다.
3. 분석 후 최초 판단 고정. 이후 차트를 별도로 분석하고 사후 비교한다. 최초 판단은 덮어쓰지 않는다. 저장은 이 브라우저의 로컬 저장소이며 서버 계정 동기화는 없다.
4. 사후 비교는 읽힌 날짜·가격 구간의 돌파/이탈 관찰이다. 복합 진입·무효화 조건 전체의 자동 검증은 아니며 누락 봉이 있으면 최초 발생 순서를 확정할 수 없다. 정확한 수익률·적중률은 계산하지 않는다.

중간 과거 후보 탐색과, 이후 봉을 실제로 가린 재분석은 구분한다. 전체 이미지로 탐색한 후보만으로 당시 정보 검증을 완료했다고 표시하지 않는다. 오른쪽 끝 검사 역시 모델의 위치 추출에 의존하므로 모델이 위치와 봉 모두를 잘못 읽으면 잡지 못할 수 있다.

## 실행 검증

- Node 규칙·서버 테스트 46개: 오래된 기준일, 종목/날짜 누락에도 구조 유지, 미확정 마지막 봉과 과거 후보 공존, 가격표 역할 분리, 과거 오류의 현재 요약 오염 방지, 최초 판단 무결성·보존, 기존 돌파 실패·첫 조정 후 회복 등.
- `scripts/check-historical-browser.mjs`: 합성 응답을 사용한 실제 Chromium UI 검증. 320/390/768/1440px 결과, 범위 편집, 최초 판단 고정 및 사후 비교, 기록 복원. 1000px 합성 이미지의 미래 300px를 잘라 최종 폭 700px인 것과 흰 마스크 픽셀, 실제 요청 이미지 폭/마스크 수를 검사했다.
- 기존 `scripts/check-browser-flow.mjs`: 업로드·붙여넣기·예시 혼동 방지·오류·기록·반응형 회귀 검사 통과.
- 화면 밖 가격표만 변경한 테스트는 **모의 관찰 응답** 비교다. 실제 이미지 두 장을 모델에 보내 동등 결과를 확인한 것은 아니다.
- 실제 OpenAI API 호출: 실행하지 못함. 이 환경에 API 키 바인딩이 없으며 첨부 사례의 실제 원본 응답도 없다. 실제 이미지 OCR 정확도, 실제 마스킹한 사례의 모델 판독, 모델의 가격표 불변성은 미검증이다.

`docs/screenshots/historical-desktop.png`와 `historical-mobile.png`는 합성 데이터의 수정 UI 화면이며 우리기술 실호출 결과가 아니다.
