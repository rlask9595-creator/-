# Chart Signal v3 원인 진단과 검증

## 확인된 코드 결함 / 확인하지 못한 실제 응답

사용자가 보고한 '고점·저점 구조 / 판독 보류 / 미보유자'는 서버의 기본값이다. 해당 호출의 AI 원문과 서버 응답은 기존 앱에서 저장하지 않았으므로 실제 요청의 원인을 확정할 수 없다. 현재 작업 환경에 CHART_API_KEY/OPENAI_API_KEY가 없어 실제 OpenAI 호출은 하지 않았다. 키 존재 여부만 확인했고 값과 사용자 이미지, 원문 응답을 로그/파일로 남기지 않았다.

| 점검 | 기존 코드에서 확인한 원인 | 변경 |
|---|---|---|
| 이미지 판독 | 긴 차트의 모든 봉을 180개 이내로 연속 추출하도록 요구. 불가능하면 전체 low/unreadable | 전체 구간 흐름 관찰 → 최근 최대 80봉 → 과거 전환 구간 최대 6개(각 최대 180봉, 총량 가급적 300봉 이하). 구간 안의 봉을 건너뛰지 않음 |
| 전체 품질 게이트 | evidenceQuality=low이면 priceSequence를 null로 넘겨 유효한 국소 관찰도 삭제 | 현재·각 역사 구간의 국소 품질을 별도로 사용. 전체 품질 low만으로 삭제하지 않음 |
| 봉 마감 | 첫 completed=false에서 모든 탐색 중단 | 과거 봉은 마감된 자료로 정규화, 마지막 봉만 사용자 closed/open/unknown 선택 적용. 내부 수치 판독 단절에서는 새 연속 구간 시작 |
| 형식 오류 | 누락/잘못된 형식은 원래도 HTTP 502였음 | '패턴 없음'으로 바뀐 것이 아님. MODEL_SCHEMA_INVALID와 MODEL_OUTPUT_INCOMPLETE로 오류를 구분 |
| 관찰 소실 | 제목·요약·지지저항·근거를 일괄 기본 문구로 교체; trend에도 결론 반복 | AI 관찰 필드, 서버 판정, 실제 표시 내용을 요청 메모리에 별도 보관. 관찰 지지저항은 '순서 미검증'으로 표시하여 보존 |
| 표시 혼동 | 미확인/실패를 하나로 표현, 현재 상태와 과거 후보가 결합 | 현재 행동 / 과거 후보 / 판독 불가 항목 분리. 확인·미충족·실패·확인 불가를 별도 표시 |

`assessment.diagnostics`와 화면의 '분석 과정 확인'에서 AI 최초 관찰 필드 → 서버 판정 → 화면 문구를 비교한다. 모든 원시 모델 토큰을 영구 저장하지 않으며, 이미지와 API 키는 diagnostics에 들어가지 않는다. 결과 복사에 이 비교 정보가 포함된다. 이전 요청의 원문을 새 기능으로 복원할 수는 없다.

## 판정과 화면

- `chartOverview`는 전체 구간의 횡보/상승/조정/하락을 관찰하는 모델 출력이다. 검증된 매매 후보와 구분한다.
- 현재와 과거의 연속 봉열에 동일한 순서 엔진을 적용한다. 구간의 역할(장기 횡보, 상승 중 짧은 횡보, 수개월 조정)은 모델의 맥락 관찰이며, 가격 조건을 통과해야 후보가 된다.
- 새 지역 저항을 찾아 재돌파를 판독하고, 이전 저항 지지 후 직전 봉 고가 회복을 눌림 회복으로 판독한다. 반등 실패 경로에 더해, 주요 지지 이탈+이전 봉폭 중앙값 대비 2배 이상 종가 하락+거래량 증가 관찰이 함께 있으면 급격한 훼손 후보를 기록한다. 정밀 시세가 아닌 이미지 근사 휴리스틱이다.
- 과거 더 높은 저항이 현재 가격에서 최근 봉폭 2배 이내에 있으면, 돌파가 유효해도 미보유자는 신규 진입 대기한다. 동일 가격축으로 판독된 구간끼리만 비교한다.
- '모름'은 마지막 봉을 제외한다. '마감 완료'는 사용자 제공 정보로 기록한다. 이전 봉의 불확실한 수치가 마감 선택 때문에 정확한 값으로 바뀌지는 않는다.
- 가격은 정확 관찰/근사/상대 위치/불가로 구분한다. 픽셀에서 추출해 엔진이 산출한 수준은 항상 근사이다. 가격축이 없으면 숫자 좌표를 원화처럼 노출하지 않는다.
- 상단: 종목·주기·투자 기간·보유 여부 → 행동 제목 → 핵심 이유 → 상태별 근거 3개 → 다음 확인 조건 → 판단 변경 조건. 세부 지표와 구간 흐름, 과거 매수·매도 후보, 부족 항목, 비교 정보는 하단.
- 후보마다 형성 위치/최초 확인 위치/근거/판단 변경 조건을 남긴다. 미래 봉을 덧붙여 기존 엔진 이벤트가 소급 변경되지 않는지 접두 구간 비교로 테스트한다.

## 검증 결과

`npm test`: 37개 통과. 순서 규칙 11개, 평가 구조 14개, 서버/API 모의 응답 12개. 디자인 검사 통과.

| 규칙 사례 | 결과 |
|---|---|
| 윗꼬리 돌파 / 종가 돌파 뒤 실패 | 미확인 / 실패 구분 |
| 첫 조정 → 이전 고점 회복 | 실패 시나리오 해제, 자동 매도 없음 |
| 낮은 고점 → 반등 지지 → 조정 저점 이탈 | 비중 축소 → 구조 훼손 구분 |
| 지지 급락+큰 봉+거래량 증가 | 반등 전 급격한 훼손 경고. 거래량 미확인은 이 경로로 승격하지 않음 |
| 재횡보 재돌파 / 수개월 조정 구간 / 눌림 지지 회복 | 가격 조건을 통과한 후보만 기록 |
| 마지막 봉 미확정 / 전체 품질 low | 판독 가능한 과거 후보 보존 |
| 내부 봉 수치 누락 | 해당 구간 단절, 이후 독립된 연속 구간 탐색 가능 |
| 정상 횡보와 정보 부족 | 신규 진입 대기 / 분석 정보 부족 구별 |
| 필드 누락·출력 중단 | 명시적 API 오류. 패턴 없음으로 변환하지 않음 |
| 미래 봉 추가 | 기존 이벤트와 최초 확인 시점 유지 |

Chromium에서 320/390/768/1440px 결과, 상단 상태와 근거 3개, 후보 위치선, 마지막 봉 설정, 예시/실제 버튼 경로, 이미지 전달, 오류 처리, 세션 기록을 확인했다. 브라우저 API 응답은 합성 데이터이며 실제 이미지 인식 검증이 아니다. 스크린샷도 합성 UI 검증 결과다.

## 우리금융지주 실제 이미지 검증 범위

이전에 제공된 사진의 차트는 대화에서 육안으로 확인할 수 있으나 작업 환경에 원본 이미지 파일이 없고 실제 API 키도 없다. 원래 '판독 보류' 요청의 모델 원문도 없다. 따라서 **실제 API 재판독, 미래 봉 가림 검증, 최초 확인 날짜 확정은 미실시**이다.

| 사용자가 지정한 검토 구간 | 이번에 확인한 범위 |
|---|---|
| 2025년 4월 말~5월 초 | 이전 사진에서 장기 횡보 이후 상승으로 이동하는 흐름은 보임. 해당 시점 이후를 가린 판독 미실시로 최초 돌파 신호 확정 불가 |
| 2025년 6월 | 상승이 진행되는 구간은 보임. 짧은 횡보 상단과 최초 종가 확인 봉은 마스킹 검증 필요 |
| 2025년 12월 | 오른쪽 고점 갱신 뒤 조정 형태는 보이나 모든 날짜/종가를 정확히 읽을 수 없음. 지지 재시험 확인 여부 미검증 |
| 2026년 2월 급락 | 이전 첨부 사진에서는 해당 구간을 확인할 수 없음. 결과를 만들어내지 않음 |
| 이후 반등 실패 | 해당 기간이 보이는 별도 이미지가 필요. 정답 후보로 강제하지 않음 |

전체 사진을 본 이 관찰은 당시 정보만으로 판정한 결과가 아니다. 실제 검증할 때는 선택 시점 오른쪽의 가격봉·거래량·지표와 미래 가격 주석/현재가/전체기간 매물대 등도 실제로 가린 별도 이미지를 사용해야 한다. 전체 이미지를 보내 '무시하라'는 지시만 주는 것은 인과성 검증이 아니다. 종목·날짜·가격은 운영 코드에 고정하지 않았다.

## 남은 한계

비전 모델의 봉 추출·구간 선택이 정확한지는 별도 실호출 검증이 필요하다. 현재 구현은 규칙 엔진의 인과성을 검증했으며 모델의 전체 이미지 판독에 미래 영향이 없다고 보장하지 않는다. 매물대·평균 매입가·커서값·별도 현재가를 신호 근거로 쓰지 말라는 지침은 추가했지만 실제 이미지에서의 준수율은 아직 측정하지 않았다. 최근 구간/역사 구간 추출이 길면 API 비용·응답 시간이 증가할 수 있고, 응답이 중단되면 명시적인 오류와 구간 확대 요청을 보여준다.
