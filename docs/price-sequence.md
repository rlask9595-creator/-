# 가격 순서 판독 v1

## 변경 범위

- `sequence-policy.mjs`: 이미지 봉 추출 스키마·지침, 순차 상태 판정, 최초 확인 시점과 당시 저항 스냅샷.
- `analysis-policy.mjs`: 기존 봉패턴 단독 매매 허용을 제거하고 가격 순서 결과를 최종 의견으로 사용.
- `indicator-policy.mjs`: MA 독립 신호/반대 지표 자동 거부를 제거. 갭·MA·볼린저 설명은 보조로 보존.
- `server.mjs`: 중첩 스키마 검증 및 보유 여부 전달.
- `public/app.js`: 결과 복사에 형성 위치 / 확인 위치의 신호 기록 추가. 기존 제목에 현재 패턴 / 단계 / 관점을, 근거 목록에 ①~⑤를 전달하므로 렌더러·CSS·HTML·디자인 baseline은 변경하지 않음.
- `test/sequence.test.mjs`, `test/server.test.mjs`: 규칙 및 API 통합 테스트.

## 판정 계약과 한계

연속 봉을 왼쪽부터 처리한다. 모델이 추출하는 OHLC 근사치와 20일선은 원시 거래소 데이터가 아니다. 180개보다 많거나 봉이 너무 밀집하여 연속 추출이 불가능하면 확대를 요청하고 보류한다. 가격축 미확인은 동일 좌표계의 상대 높이를 사용하며 원화로 표시하지 않는다. 봉 마감이 확인되지 않거나 데이터가 잘못된 지점 이후에는 판정을 진행하지 않는다. API 모델의 기존 signal 필드는 최종 권한이 없다.

현재 구현의 명시적 휴리스틱(성과 검증된 파라미터가 아님):

- 좌우 2개 봉보다 높은/낮은 봉을 스윙으로 사용한다. 오른쪽 2개 봉이 생긴 시점부터만 사용한다.
- 최소 3봉 떨어진 반복 고점을 최근 최대 20봉의 중앙 봉폭 ×0.75 이내에서 구간으로 묶는다. 봉폭은 고가−저가이다. 돌파 후 구간은 고정한다.
- 반복 저항 뒤 중앙 봉폭 이상 조정이 있었고 완성봉 종가가 상단을 넘어야 돌파 후보이다.
- 신규 진입은 저항 위 거리가 돌파 당시 중앙 봉폭 ×2 이내인 경우만 후보이다. 이를 넘으면 기존 돌파는 유효할 수 있어도 신규 진입은 대기한다.
- 최근 20봉 상승 폭이 중앙 봉폭 ×4 이상인 상태에서 주요 지지 또는 식별된 20일선을 종가로 잃으면 첫 경고이다.
- 첫 하락 뒤 직전 봉 고가를 종가로 회복하면 반등 시도이다. 반등 고점 뒤 직전 봉 저가를 종가로 잃은 시점에 낮은 고점을 확인한다. 반등 고점을 다시 높이면 꺾임을 재확인한다.
- 반등 중 확인된 저점 지지 이탈은 비중 축소 검토, 최초 조정 저점까지 이탈하면 구조 훼손이다. 중간 반등 지지가 따로 형성되지 않았다면 축소 단계를 건너뛰고 구조 훼손을 기록할 수 있다.
- 이전 고점 종가 회복은 실패 시나리오를 해제한다. 구조 훼손 이후 새 구간의 고점·저점만으로 새 저항을 형성한다. 과거 이벤트는 삭제하지 않는다.

이는 사용자 기준을 재현 가능한 초기 규칙으로 구현한 것이며 모든 차트의 재량적 해석을 대체하지 않는다. 스윙 확인 지연, 변동성에 따른 민감도, 이미지 추출 오차가 있다. 중기 일봉 중심의 기준이며 다른 주기의 20기간선을 자동으로 20일선으로 해석하면 안 된다.

## 미래 정보 검증 범위

테스트는 동일한 추출 봉열의 모든 접두 구간을 재실행하고, 전체 실행에서 해당 시점까지 기록한 이벤트와 완전히 같은지 비교한다. 형성 시점과 최초 확인 시점, 당시 저항 스냅샷까지 비교한다. 이는 **규칙 엔진의 인과성 검증**이다. 전체 차트를 본 비전 모델이 미래 봉에 영향받지 않는다는 검증은 아니다.

실제 이미지 시점 검증에서는 날짜 기준 오른쪽 봉을 실제로 가리고(거래량·지표 포함), 커서/선택 OHLC를 가린 별도 이미지를 입력해야 한다. 전체 이미지를 넣고 '무시하라'고 지시하는 것은 검증으로 인정하지 않는다. 가린 이미지·가림 경계·추출 봉·응답을 함께 보관해야 한다.

## 대덕전자 사례 — 실제 판독 미실시

최초 구현 요청에는 이미지가 없었고, 후속 배포 요청에서 네 장을 확인했다. 아래는 **시점별 검증 계획**이다. 첨부 이미지는 대화에서 볼 수 있지만 실행 환경에 파일로 제공되지 않아 오른쪽 봉을 물리적으로 가린 API 검증은 아직 수행하지 않았다. 종목·날짜·가격은 운영 코드에 넣지 않았다.

| 사례 | 확인할 구간 | 기대되는 조건부 판독 |
|---|---|---|
| 1 | 1월 말 이후 오른쪽 약 57,500원 | 지지 접촉만이면 눌림 관찰. 저점 유지·단기 고점 회복과 저항 상단 종가 돌파를 별도 확인 |
| 2 | 3월 중순 6.7만~7만 반복 저항 / 5월 오른쪽 | 저항 근거 봉과 첫 종가 돌파 시점 기록. 5월은 기존 돌파 유효성과 추격 진입 여부 분리 |
| 3 | 5월 조정 / 6월 1일 이후 / 6월 중순 반등 | 고저점 상승·지지 유지가 보유 근거. 첫 경고→반등 시도→실제 꺾임→반등 지지 이탈 순서 확인 |
| 4 | 6~7월 하락 / 가을 새 상승 | 이후 하락으로 앞선 매도 시점을 소급하지 않음. 새 상승 구조는 새 구간의 근거로 판독 |

실제 이미지 검증, 모델 정확도·수익률 평가는 아직 수행하지 않았다. 합성 OHLC 규칙 테스트와 모의 API 테스트를 실제 이미지 검증으로 간주하지 않는다.

## 실행 결과

`npm test`: 19개 통과(순서 규칙 10개, 모의 API/서버 9개). 디자인 해시 검사 통과. Chromium에서 데스크톱·모바일 배열, 새 결과 제목/5개 근거 표시, 기록·설정·오류 복구 및 실제 클립보드 Ctrl+V·이미지 교체를 확인했다. 브라우저의 분석 응답은 합성 데이터이며 실제 비전 판독 테스트는 아니다.

## 후속 첨부 이미지의 육안 관찰 (API 검증과 별도)

- 1번: 오른쪽 57,500원 표시는 보이지만 왼쪽 상단 OHLC는 2만 원대로 커서 선택값이다. 1월 말 67,700원 고점 이후 조정이 보이며, 오른쪽 가격만으로 매수 확인을 선언할 수 없다. 저점 방어와 단기 고점 회복, 이후 저항 돌파를 확인해야 한다.
- 2번: 3월 구간의 상승과 오른쪽 169,200원까지 진행한 상승은 구분해야 한다. 117,633원 평균 매입가선과 84,000원 안내선을 저항 근거로 자동 채택하면 안 된다. 과거 돌파와 현재 추격 진입 판단은 별도다.
- 3번: 6월 1일 198,000원 고점 뒤 첫 하락, 이전 고점보다 낮은 반등, 재하락이 순서대로 보인다. 정확한 최초 매도 확인 봉은 6월 이후를 가린 여러 접두 이미지로 검증해야 하며, 전체 화면만 보고 날짜를 소급 확정하지 않았다.
- 4번: 여름 하락 이후 가을 반등과 재조정은 새 구조의 대상으로 보인다. 140,200원 최신 가격과 117,633원 평균선·83,800원 안내선을 구분해야 한다. 가을 장면으로 6월 매도 판단의 최초 확인 시점을 바꾸지 않는다.

이 관찰은 전체 이미지를 본 육안 설명이며, 인과성을 검증한 앱 출력·비전 API 결과 또는 투자 권고가 아니다. 실제 시점별 검증 완료로 집계하지 않는다.

## v2: 확대 화면과 과거 매수 후보 표시

메뉴·설정 글자를 확대하고 결과 본문은 15px로 표시한다. 차트를 넣으면 미리보기가 본문 전체 너비로 펼쳐진다. '크게 보기'와 '원본 크기 / 화면 맞춤'을 지원한다. 과거 돌파 확인 이벤트의 봉 가로 좌표(x, 전체 이미지 기준 0~1)를 모델에서 추출하여 결과 차트에 번호·위치선을 겹쳐 표시한다. 좌표 미확인 시 선을 생략하고 봉 위치만 설명한다. 표시되는 시점은 패턴 발생 봉이 아닌 종가로 확인한 봉이다. 당시에도 돌파 상단에서 2봉폭보다 멀면 '추격 진입 대기'로 표시한다. 이는 최적 수익 시점의 사후 추천이 아니다.

20개 규칙/서버 테스트, 모바일·데스크톱 브라우저 검증 및 붙여넣기 확인. 실제 API는 사용량 한도 문제가 해결되어야 별도 검증 가능하다. 정책 버전 `price-sequence-v2`.

## 예시/실제 분석 혼동 수정

업로드한 차트가 있어도 예시 버튼을 누르면 고정 샘플이 표시되는 경로를 수정했다. 이미지가 있으면 기존 두 예시 버튼은 '내 차트 분석'으로 바뀌고 업로드 이미지의 `/api/analyze` 요청으로 연결된다. API 키가 없으면 설정을 열고, 요청 실패 시 이전 결과·복사 상태를 비운다. 샘플로 대체하지 않는다. 이미지를 제거하면 예시 기능이 복원된다. 디자인 구조는 변경하지 않았다.

`node scripts/check-browser-flow.mjs`는 로컬 서버와 Chromium이 필요하다. 실제 브라우저에서 이미지 원문 전송 일치, 두 버튼 경로, 키 미설정, 429 응답 시 샘플 미표시, 이미지 제거 후 복원을 검증한다. 응답은 모의 데이터이며 업로드 종목의 실제 비전 분석 검증은 아니다.
