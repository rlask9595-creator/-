# Chart Signal

차트 이미지를 올리면 추세·패턴·거래량·지지/저항을 읽고, 조건부 **매수 검토 / 보류 / 매도 검토** 의견을 보여주는 한국어 웹앱입니다.

## 실행

Node.js 24 이상. 외부 패키지 설치와 빌드 단계는 없습니다.

```sh
cd /workspace/-
npm start
```

기본 포트는 3000이며 `PORT`로 변경할 수 있습니다. 개발 중 자동 재시작은 `npm run dev`를 사용하세요. 현재 클라우드 환경에서는 로컬 서버 실행에 샌드박스 네트워크 권한이 필요할 수 있습니다.

## 실제 이미지 분석 연결

OpenAI Responses API의 `gpt-4.1-mini`를 사용합니다. 다음 중 하나를 선택하세요.

- 앱의 **분석 연결 설정**에서 본인의 OpenAI API 키를 입력합니다. 키는 탭 메모리에만 보관하며 분석 요청 때 서버로 전송합니다. 새로고침하면 삭제됩니다.
- 환경 설정에서 `CHART_API_KEY`를 안전하게 등록합니다. 일반 로컬 환경에서는 `.env.example`을 `.env`로 복사한 뒤 값을 넣을 수 있습니다. 기존 `OPENAI_API_KEY` 환경 변수도 지원합니다. 서버 키가 입력된 키보다 우선합니다.

서버는 `https://api.openai.com/v1/responses`로 연결하므로 제한된 네트워크에서는 `api.openai.com` 허용이 필요합니다. 시작 명령은 Node의 환경 프록시 지원을 사용하며 TLS 검증을 유지합니다. 키를 코드나 Git에 넣지 마세요. 설정 변경 후 서버를 다시 시작하세요.

스크린샷은 사용자가 붙여넣기 동작을 할 때만 읽습니다. 클립보드 읽기 권한을 요구하거나 자동으로 클립보드를 조회하지 않습니다. 새 이미지를 붙여넣으면 기존 미리보기를 교체합니다. API 키 입력창 등 텍스트 필드의 붙여넣기는 그대로 동작합니다.

API 키가 없어도 화면과 **예시 분석**을 살펴볼 수 있습니다. 예시에는 가상 데이터와 미리 작성한 설명을 사용하며 실제 업로드 분석과 명확히 구분합니다. 연결 준비 표시는 키 존재 여부이며 API 권한과 잔액을 보증하지 않습니다.

## 사용

1. 차트 영역을 캡처해 복사한 뒤 앱 페이지에서 **Ctrl+V / ⌘V**로 붙여넣습니다. Windows는 **Win+Shift+S**, Mac은 **Control+⌘+Shift+4**로 영역을 클립보드에 캡처할 수 있습니다. 파일 선택·끌어놓기도 지원합니다. PNG / JPG / WEBP, 8MB 이하, 가로·세로 각각 100px 이상입니다.
2. 투자 기간과 보유 여부를 선택합니다.
3. **차트 분석하기**를 누릅니다.
4. 매매 관점, 판단의 근거와 위험, 다음 확인 조건과 판단 무효화 조건을 읽습니다.

확인되지 않는 가격·종목·시간축은 추측하지 않습니다. 차트가 아니거나 판독할 수 없는 이미지의 의견은 보류로 제한합니다. 결과 복사와 최근 5건의 세션 기록을 지원합니다. 기록과 이미지도 탭 메모리에서만 유지합니다.

## 검증

```sh
npm test
```

서버 테스트 11개: 정적 파일·설정 상태, 이미지·입력 검증, API 요청/구조화된 결과, 판독 불가 처리, 인증·한도·네트워크 오류, 비정상 응답 차단, 패턴 확인·추세·방향 검증, 부족하거나 잘못된 패턴 근거 처리. API는 모의 응답으로 검증하므로 과금되지 않습니다.

Chromium에서 데스크톱(1440px)·모바일(390px) 레이아웃, 업로드, 예시 표시, 설정, 결과, 기록, 오류 복구를 검증했습니다. 실제 API 키를 통한 분석 품질과 연결은 아직 검증하지 않았습니다.

## 데이터와 한계

이미지와 키는 이 앱의 디스크나 로그에 저장하지 않습니다. 분석 요청 시 이미지와 분석 기준이 OpenAI로 전송되며 `store: false`를 설정합니다. 제공자의 데이터 처리 정책은 별도로 적용됩니다. 서버는 외부 오류 원문이나 키를 사용자에게 노출하지 않습니다.

이 앱은 개인 개발용입니다. 공개 서비스로 배포하기 전 HTTPS, 사용자 인증, 사용자별 사용량 제한과 과금 제어를 추가하세요. 서버 키를 설정하면 해당 서버 이용자가 그 계정의 API 비용을 발생시킬 수 있습니다.

차트 이미지의 시점과 범위만 분석합니다. 실시간 시세·뉴스·재무정보는 반영하지 않으며 가격축, 이동평균 또는 패턴을 잘못 읽을 수 있습니다. 판독 근거 수준은 수익 확률이 아닙니다. 분석 결과는 투자 판단의 참고 자료입니다.

## 화면 디자인

크림·피치 배경, 오렌지 포인트, 상단 내비게이션과 반응형 카드 레이아웃을 사용합니다. Pretendard 가변 폰트는 앱에 포함되어 별도 폰트 서비스 연결 없이 표시됩니다. 폰트의 SIL Open Font License는 `public/fonts/OFL.txt`에 포함했습니다.

## 봉차트 분석 기준 v2

사용자가 제공한 교재 발췌의 반전형·지속형 분류를 `analysis-policy.mjs`에 반영했습니다. 샛별형/도지, 새벽별·저녁별, 해머형·교수형·유성형, 상승·하락장악형, 적삼병·흑삼병을 점검합니다. 선행 추세, 캔들 색상 규칙, 몸통·꼬리, 최근 패턴 위치, 후속 확인, 거래량·지지/저항의 한계를 결과에 함께 표시합니다.

작은 몸통 한 개와 3봉 새벽별·저녁별을 구분합니다. 장악형의 몸통 포괄과 교재의 엄격한 고가·저가 포괄 조건도 구분합니다. 색상만으로 양봉·음봉을 단정하지 않습니다.

후속 확인이 없는 후보, 낮은 판독 근거, 선행 추세·봉 방향 불명확, 방향 상충은 서버에서도 보류로 제한합니다. 완성된 과거 패턴을 현재 신호로 사용하지 않도록 지시합니다. 이 검사는 모델이 보고한 구조화된 관찰을 검증하며, 원본 이미지의 봉 형태를 서버가 수치로 독립 검증하는 것은 아닙니다.

현재 자동 검증은 모의 응답을 통한 요청·응답 및 보류 규칙 검증입니다. 실제 차트 정답 데이터에 대한 패턴 인식 정확도, API 실호출 품질, 수익률·백테스트는 검증하지 않았습니다.

## 갭·이동평균·볼린저 통합 기준 v3

`indicator-policy.mjs`에 사용자 교재의 추가 기준을 반영했습니다. 정책 버전은 `technical-v3`입니다.

- 갭: 인접 봉의 고가·저가 사이 가격 공백, 상승/하락 방향, 경계, 미메움/부분/완전 메움, 실제 재접근의 지지·저항 반응을 구분합니다. 메움만으로 추세 반전을 확정하지 않습니다.
- 이동평균: 범례로 식별되는 5·20·60·120기간선을 대상으로 가격 위치·기울기·최근 종가 돌파를 점검합니다. 일봉에서만 ‘일선’이라고 부릅니다. 5선 돌파와 기울기가 함께 확인되고 20선 방향도 일치해야 독립 매매 근거로 사용할 수 있습니다. 60·120선은 보조 흐름이며 실제 수급·경기를 증명하지 않습니다.
- 볼린저: 식별 가능한 상단·하단·중심선, 시장의 추세/횡보/수축 상태, 재진입 후 확인을 점검합니다. 밴드 터치만으로 매매하지 않으며 추세장에서 밴드 워킹이 가능함을 반영합니다. ±2표준편차의 정규분포 설명을 실제 주가의 95% 포함 보장이나 각 2.5% 돌파 확률로 적용하지 않습니다.
- 통합: 기존 확인된 봉패턴 또는 확인된 5/20선 근거를 기본으로 사용합니다. 확인된 반대 패턴, 20선의 반대 기울기, 미메움 갭의 반대 재시험, 횡보 밴드의 반대 재진입이 있으면 보류합니다. 갭·밴드만으로 방향 의견을 만들지 않습니다. 모델의 보류 의견을 매수/매도로 자동 승격하지 않습니다.

기존 v2의 봉패턴만 허용하던 매매 제한은 위 통합 규칙으로 확장했습니다. 지표별 관찰·미확인 이유는 내부 구조화 결과와 결과 복사 내용에 포함됩니다. 화면에는 승인된 기존 결과 템플릿을 사용합니다. 화면에 없는 지표를 계산하거나 뉴스·경기 상황을 추정하지 않습니다. 규칙 테스트는 모의 관찰값을 대상으로 하며 실제 이미지 인식 정확도나 수익성 검증과는 다릅니다.

## 디자인 유지

사용자가 승인한 크림·오렌지 디자인은 `design/baseline/`에 보관합니다. 분석 기준 추가 시 별도 결과 카드가 생기지 않도록 원래 결과 레이아웃으로 복원했습니다. 상세 지표 근거는 기존 결과 복사로 확인할 수 있습니다.

`npm run check:design`은 HTML·CSS·폰트·예시 이미지·결과 렌더러의 변경을 검사하며 `npm test` 실행 전에도 동작합니다. 기능 개발에서는 디자인을 유지하고, 명시적인 디자인 변경 요청이 있는 경우에만 기준을 갱신합니다. 자세한 작업 규칙은 `AGENTS.md`를 확인하세요.
